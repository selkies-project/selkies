# Selkies 2.2.0

## What Selkies 2.2 brings

Selkies 2.2.0 ships with [`pixelflux` 2.2.2](https://github.com/selkies-project/pixelflux/releases/tag/2.2.2) and [`pcmflux` 2.2.1](https://github.com/selkies-project/pcmflux/releases/tag/2.2.1).

- **One dashboard, two layouts.** The sidebar and the Wish toolbar are now layouts of the one bundled dashboard, switched live from the page. `--ui-layout` picks the one a page starts on, or locks one.
- **The display follows the page you use.** A page of another tab or device takes its display once the owner's tab is hidden, or once its user acts through it while the owner's page sits unused. Moving from a phone to a desktop no longer leaves the desktop on the phone's picture.
- **A change reaches the stream as it lands.** `pixelflux` 2.2.2 publishes a change at once on XShm, DRI3, and the Wayland compositor, instead of at the next frame tick. On the compositor, an application's own redraw now reaches the encoder in 2.6 ms at the median, down from 11. DRI3 now also works on NVIDIA's X driver before 595.
- **Congestion control that cuts less.** WebSockets no longer cuts a desktop's stream down to its own trickle, nor sizes a window switch's backoff from the trickle before it. On a 3 Mbit/s path, those cuts now stop at 1.5 Mbit/s or above, where they used to reach 0.55 to 1.4.
- **A file manager in the Wish layout**, browsing over a JSON API, with folder downloads as zip archives (#468, by @vishalkadam47).
- **Touch and keyboard:** trackpad mode right-clicks on a finger held still, the on-screen keyboard rises in Edge on Windows, and every control the keyboard reaches shows its focus.

## Upgrading from 2.1.0

- **The tools are `selkies session`, `selkies resize`, and `selkies gpu-probe` alone.** The `selkies-session`, `selkies-resize`, and `selkies-gpu-probe` console scripts are gone. The AppImage takes `session`, `resize`, or `gpu-probe` as its first argument, and no longer the hyphenated names.
- **The Wish dashboard is a layout of the bundled one.** `--ui-layout wish` (`SELKIES_UI_LAYOUT=wish`) serves it, and `wish,default` starts there with the layout toggle shown. A deployment that served the build of `addons/selkies-dashboard-wish` as its web root drops that root and sets the layout instead; the addon is gone.
- **`/api/screenshot` answers a busy or late screenshot with a 503 and `Retry-After: 1`**, which a client retries; it used to answer 404. An unknown display stays a 404, and any other failure is a 500. Every screenshot handed out is now a `screenshot` event on the audit trail, with the role of the credential that took it.

## Running this build

**Container:** the desktop, a browser, and an audio stack, with nothing to install:

```bash
docker run --name selkies -it -d --rm --shm-size=2g -p 8080:8080 \
    ghcr.io/selkies-project/selkies/desktop:2.2.0-ubuntu26.04
```

Open <https://localhost:8080>, accept the container's self-signed certificate, and log in as `ubuntu` with the password `mypasswd`. Set another with `-e PASSWD=` before anyone else can reach the session. `debiantrixie` is the other flavor, and `latest` now points at this release. The flags for NVIDIA, Intel, and AMD GPUs are in [Getting Started](https://docs.selkies.io/start).

**PyPI:** the wheel and the sdist, with `pixelflux` 2.2.2 and `pcmflux` 2.2.1 resolved from PyPI as well, on Python 3.9 through 3.15:

```bash
pip install selkies
```

**AppImage:** runs from wherever you put it, on any distribution with glibc 2.28 or newer. Given `session` as its first argument, it starts a whole session with its own display and sound server:

```bash
APP="selkies-2.2.0-$(uname -m).AppImage"
curl -O -fsSL "https://github.com/selkies-project/selkies/releases/download/2.2.0/${APP}"
chmod +x "./${APP}"
"./${APP}" --public --port=8080 --basic-auth-user=user --basic-auth-password=mypasswd
```

**Native packages:** install a private environment at `/opt/selkies` and put `selkies` on `PATH`:

```bash
. /etc/os-release
DISTRO="${ID}$([ "${ID}" = "ubuntu" ] && echo "${VERSION_ID}" || echo "${VERSION_CODENAME}")"
PKG="selkies-2.2.0-${DISTRO}-$(dpkg --print-architecture).deb"
curl -O -fsSL "https://github.com/selkies-project/selkies/releases/download/2.2.0/${PKG}"
sudo apt-get install -y "./${PKG}"
```

[Native Install](https://docs.selkies.io/native) has the `.rpm`, `.apk`, and `.pkg.tar.zst` lines. [Jupyter, Coder, and Open OnDemand](https://docs.selkies.io/platforms) covers `selkies session` and the three integrations.

**Checksums and provenance:** every file here is listed with its SHA-256 sum in `SHA256SUMS`, and GitHub attests the build provenance of each. You can check a download with either:

- `sha256sum --check --ignore-missing SHA256SUMS`
- `gh attestation verify "./${PKG}" --repo selkies-project/selkies`

## Changes since 2.1.0

### Congestion control and streaming

- **A desktop's trickle is judged by what its acknowledged frames sent.** When motion started on a still screen behind a longer path, the burst not yet acknowledged made the trickle look like a stream filling the queue, and the rate was cut to the trickle's (8000 to 153 kbps on the test rig). The queue's app-limited test now compares the delivery with what the stream sent of the same frames.
- **A window switch's backoff is sized from what the path carried through the burst**, not from the window's rate, which the trickle before it dilutes.
- **A queue the rate cuts leave standing is taken for the path**: a longer path's or other traffic's delay becomes the floor, so the stream runs at its share rather than at the least rate.
- **A still screen's target rises no further than the capacity its path showed**, and no further on a tick that measured no offer than on a trickle. A stream a hidden tab restarted is measured from its restart.
- **Each cut's log line names how late the server's own event loop ran**, which tells a slow host from a slow path.
- **WebRTC:** a still screen's cleanup is kept within the pace its pacers drain, a lowered video bitrate applies at once, and frames Selkies drops are reported to the encoder as withheld.
- **WebRTC's SCTP** takes a TSN exactly 2^31 away as old in every comparison (found by OSS-Fuzz).

### Several pages, one display

- **A display goes to the page in view once its owner's tab is hidden**, and to the page its user acts through (a key, a click, a touch, a pointer move, a gamepad button, or an IME's text) once the owner's page has sat unused for three seconds. Over WebSockets, a page that joined beside an owner whose hidden tab stopped the capture used to show no video.
- **A page's size is replayed each time it owns its display**, and over WebRTC the old owner's path is forgotten when a page takes the display over, as WebSockets does.
- Both pages' tabs are logged when a controller joins or takes a display over.

### Dashboard

- **One dashboard with live layout switching** (by @thelamer): the sidebar and the Wish toolbar share one backend, the apps window opens fast, Wish windows drag without the 150 ms delay, and its items stay on screen when the window resizes. `--ui-layout` sets the starting layout or locks one.
- **One stats view and one panel catalog for every layout**, each panel listed once with when it shows.
- **A file manager over a JSON API in the Wish layout** (#468, by @vishalkadam47), with details, list and card views, dotfiles, folder downloads as zip, and a phone layout. Uploads go through the core's uploader into the folder shown. Archives are packed without following links, links out of the root are left unreported, listings are bounded, and responses carry no server paths or set-ID bits.
- **Readable everywhere:** contrast held to WCAG AA in both themes and layouts, a focus indicator on every control the keyboard reaches, readable hover states and notices, one spacing rhythm, and a light theme. The toolbar layout is sized by its input (touch or pointer) rather than the window's width.
- **Soft keys on demand**, with More keys in one colour and one edge, open or shut. The poor-connection mark sits above the toolbar's soft keys.
- **An app install or removal shows running on the button that started it** until the session settles it.
- **A settings tab the server hides hands its place to the first visible one**, and the layout is locked before the page connects where the server locks it.

### Input, keyboard, and clipboard

- **Trackpad mode right-clicks on a finger held still and lifted**, as direct touch does on a long press.
- **The on-screen keyboard rises where focusing a field does not**: the dashboard asks the browser for it through the VirtualKeyboard API, which Edge on Windows needs. The floating keyboard button shows on a coarse pointer only, so it stays away while a Surface's type cover is on.
- **Gaming mode** asks for its pointer lock before fullscreen spends the gesture, hands the keyboard to the stream as it starts, and releases the pointer when it ends without fullscreen. A keyboard lock the browser refuses is logged.
- **The session keeps its own clipboard when the browser hands it back.** Edge on Windows wrote a KDE cut's file list back with CRLF line ends, and the paste that followed turned the cut into text; formatted copies came back rewrapped in every browser.
- **A paste waits for the PNG of an uploaded photo** before the keys reach the session.

### Video in the browser

- **A picture a hardware encoder padded is cut to the stream's size** (by @sgtslaughta), in WebKit too, which draws a `VideoFrame` whole whatever its visible rectangle.
- **WebRTC moves a pinned capture before the root shrinks**, and revives one that ended.
- A WebSocket page keeps the status it reaches while its socket-open probes still run.

### Desktop images and integrations

- The base image runs the GPU probe and the resize as `selkies gpu-probe` and `selkies resize`; the Coder module and the Open OnDemand app start with `selkies session`, and the devcontainer feature presets the resolution with `selkies resize`.
- **A Wayland session compositor renders in software where the GPU refused the capture compositor**, where it used to stream a flat gray screen.

### Security and auditing

- **Every screenshot is on the audit trail**, with the display, its size, and the role of the credential that took it. A busy or late screenshot answers 503 with `Retry-After`.
- The website and the dashboard take zod 4.6.7 (GHSA-mrhx-c7xc-m3w5).

### Packaging and CI

- The old `selkies-session`, `selkies-resize`, and `selkies-gpu-probe` names are gone; `selkies` is the one console script.
- The test tiers measure their checks on any font and either transport, and the unit tier runs inside a Selkies desktop without its settings leaking into the suites.

## Known limitations

- **WebRTC behind NAT** may still need a STUN/TURN server; see [WebRTC and Firewall Issues](https://docs.selkies.io/firewall). The default WebSocket transport does not.
- **AV1 in WebKit:** WebKit answers that it decodes AV1 and then refuses every AV1 key frame. The client treats that as a refusal and steps to H.264 without a reload.
- **WebRTC in Firefox:** some Firefox releases paint WebRTC AV1 with the wrong color matrix; the [FAQ](https://docs.selkies.io/faq) says which.
- **10-bit in Chromium:** Chromium-based browsers decode AV1 over WebRTC at 8 bits only.
- **Gaming mode** holds the keyboard in Chromium-based browsers, Firefox 156 and later, and Safari 26.4 and later. Brave's Shields block the Keyboard Lock API by default.
- **Hosts are Linux only.** macOS and Windows support is not implemented.

## pixelflux 2.2.2

A release that publishes a change as it lands on every capture path that waits for one (XShm and DRI3 on the X server's damage report, the Wayland compositor on a client's commit) rather than at the frame timer's next tick, captures through the DRI3 1.0 servers of NVIDIA's X driver before 595, holds NvFBC to its frame rate on a still screen, and brings NVENC's 10-bit, 4:4:4, and constant-rate paths to older drivers, with fixes to the portal host capture, the still-screen cleanup under a constant rate, VA-API, and screenshots.

### Capture & Pacing

- **A change is published as it lands** : the X11 XShm and DRI3 captures and the Wayland compositor pace in windows, one frame a period at most, the first change in a period taking its frame at once, as NvFBC's driver pushes them. A change no longer waits for the next timer tick, or half a period after the last frame. A spinner's change to frame on XShm and DRI3 fell from about 11 ms to about 4 at the 95th percentile. On the compositor, a client committing on its own clock went from 11 / 18 ms (median / 95th percentile) to 2.6 / 4.3, one drawing on frame callbacks from 28 / 36 to 13 / 21, and the redraw that answers input from 17 / 17 to 8.5 / 15. The rate never rises above the cadence, which input could push past before
- **DRI3 1.0** : a server that takes buffers without a layout (the NVIDIA X driver before 595, which reports DRI3 1.0 for want of modifier support) is captured through DRI3 with a linear pool, where the capture used to decline it for XShm. On a GTX 1080 Ti at 1080p a frame is delivered in 2.6 ms against XShm's 3.6, at the same quality
- **DRI3 in streaming mode** published each change at the tick, 9-14 ms after it landed; it now takes it as XShm does
- **NvFBC on a still screen** holds its frame rate: a grab waited a whole frame for damage that would not come and the encode followed it, 55 frames a second at 60 on a Tesla K80 and 47 on an L4 in Turbo; it now waits only until the frame's deadline
- **NvFBC after a resize** : a capture whose region the root shrank under is rebuilt inside the new root rather than stopping

### Encoding & Pipeline

- **NVENC on older drivers** : HEVC and AV1 at 10 bits on drivers below API 12.2; the QP delta map handed where drivers below API 12.0 read it; constant rate in a single pass where the driver refuses the quarter-resolution first pass; a 4:4:4 request the GPU's engine lacks handed to the software encoder; a session kept across a resize where the device coded its 4:4:4 or 10-bit request down
- **VA-API** : the AV1 render size signalled where the driver pads the frame, so a client crops it to the configured size; Intel's full HEVC encoder given Skylake's block sizes and a slice quantizer every coding unit can reach, which ended corrupt streams at high quality
- **The still-screen cleanup under a constant rate** : its rate-control frames are kept to the cleanup's rate, so a sender holding the stream to its rate no longer drops the sweep's bands; a frame the sender withheld no longer starts the cleanup over; and where a sweep's least band still runs past its budget, the rest of the picture is refreshed whole rather than crawling on in ever smaller bands

### Resilience & Fixes

- **Portal host capture** : input notifications sent one at a time in the order they came; absolute pointer motion sent in the stream's logical size to every backend, and pointer motion and a finger's scroll placed in each path's space on a scaled output; the portal's cursor metadata taken at the size Mutter offers it; a stream's format kept when only the preferred size changes; a quiet host's frame kept across the capture restarts of a size change; and the stale-size screenshot error a tick never delivered dropped
- **Screenshots** : a lossless Wayland screenshot is compressed off the compositor thread, with an admission limit per display and overall; a GLES screenshot is read back on the GPU's time into a persistently mapped buffer, and its pixels handed over in a kept buffer, copied once. A 4K screenshot's tick took 14.8 ms and takes 9.5
