# Selkies 2.3.0

Selkies, pixelflux, and pcmflux are developed and released together in this repository from 2.3.0 on, at one version. The pixelflux and pcmflux repositories mirror their crates for this release cycle and stop at the next stable release; each earlier Selkies release's notes here carry the notes of the pixelflux and pcmflux releases it shipped.

## Selkies

- **A Rust server.** Selkies is one executable with no Python interpreter: the HTTP control plane on Axum and Tower, the WebSockets data plane, an in-tree WebRTC stack (ICE, DTLS, SRTP, SCTP data channels, an RTP sender with FlexFEC, pacing, and TWCC), display management, input, clipboard, gamepads, the virtual camera, audio control, and the file, printing, apps, recording, and screenshot routes. `selkies session`, `selkies resize`, and `selkies gpu-probe` are subcommands.
- **pixelflux and pcmflux are linked as Rust crates**, with no Python between them and the server.
- **`pip install selkies`** installs that executable from a `py3-none` wheel for any Python 3 on glibc 2.17 and newer (`manylinux_2_17`, CentOS 7 onward) or musl; native packages, the AppImage, and the images ship it as well, with the web client.
- **Congestion control** starts a constant-rate stream below its target and climbs to it, backs off once to what the path delivered when a queue stands, and paces WebRTC from the steered rate.
- **WebSockets** streams keep one reference frame on every encoder but NVENC; a frame a page drops is repaired with a key frame.
- **Striped H.264 is removed**: software H.264 codes the whole frame. **Turbo** defaults to off.
- **Desktop image**: labwc and Openbox in place of LXQt, one terminal (`selkies-terminal`: foot on Wayland, xfce4-terminal on X11), one right-click menu on both backends, and proot-apps on the session's PATH.

## pixelflux

- **A Rust library first**, with the Python bridge behind the `python` feature, which the wheels turn on.
- **Patched codecs in every build**: x264, x265, libvpx, and SVT-AV1 are built with the patches under `crates/pixelflux/patches` and linked in, so the blocks the block ledger holds still are skipped, copied only where they changed, or coded as skips.
- **X11** reads Xvfb's shared framebuffer in place, and an 8-bit 4:2:0 x264 session converts the tiles the server drew straight into NV12, which x264 encodes in place.
- **CPython 3.11 stable-ABI wheels**: each Linux platform carries one `cp311-abi3` wheel, for GIL-enabled CPython 3.11 and newer. The native frame buffer protocol requires the 3.11 limited API; free-threaded interpreters are not supported. Ordinary source builds retain the full CPython API on 3.9 and newer; an older interpreter builds from source rather than using the `cp311-abi3` wheel. The platforms are `manylinux_2_17` (glibc 2.17, CentOS 7 onward) and `musllinux_1_2`, each for x86_64 and aarch64.

## pcmflux

- **The Rust API is split from the Python bridge**, behind the `python` feature, and both configurations are tested.
- **libpulse 17.0 in every wheel**: PulseAudio's client libraries alone, with no D-Bus, systemd, X11 client, or codec libraries, and memfd shared memory.
- **CPython 3.11 stable-ABI wheels**: each Linux platform carries one `cp311-abi3` wheel, for GIL-enabled CPython 3.11 and newer. The native audio-frame buffer protocol requires the 3.11 limited API; free-threaded interpreters are not supported. Ordinary source builds retain the full CPython API on 3.9 and newer. The platforms are `manylinux_2_17` (glibc 2.17, CentOS 7 onward) and `musllinux_1_2`, each for x86_64 and aarch64.
