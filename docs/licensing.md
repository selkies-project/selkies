## Selkies itself

Selkies is licensed under the [Mozilla Public License 2.0](https://github.com/selkies-project/selkies/blob/main/LICENSE)
(`LICENSE` in the repository, `license = "MPL-2.0"` in the workspace's
`Cargo.toml` and in `pyproject.toml`). MPL-2.0 is file-level copyleft: a
modified MPL file stays MPL when distributed, the larger work around it may be
under any license. The server's crates, the web client, the addons (Input Interposer, V4L2 interposer, fake-udev, coturn and
TURN REST helpers, universal touch gamepad), and the build and packaging scripts
all carry MPL-2.0 headers.

Categories used on this page: **copyleft** (GPL: the combined binary must be
distributed under the GPL), **weak copyleft** (LGPL and MPL: the covered files
stay under their license, and the larger work around them may be anything;
LGPL additionally requires the library stay replaceable), **permissive**
(attribution only: MIT, BSD, Apache-2.0, ISC, Zlib, PSF, ...).

## Where the GPL code is

A Selkies installation has no GPL code of its own. One dependency brings two
GPL-licensed libraries into every release build:

| Source | GPL component | How it gets in | How to leave it out |
| --- | --- | --- | --- |
| `pixelflux` (screen capture and video encoding) | libx264 (GPL-2.0-or-later), which encodes H.264 in software wherever no GPU encoder is used: the `h264enc` fallback and `h264enc-striped` alike; and x265 (GPL-2.0-or-later) behind `h265enc` in the same case | the `gpl` Cargo feature of pixelflux, which the workspace's `Cargo.toml` turns on, so the server links libx264 and x265 in every release build | name pixelflux's `openh264` feature in place of `gpl` in the workspace's `Cargo.toml`: BSD-licensed Cisco OpenH264 and kvazaar take the places of libx264 and x265; VP8/VP9 (libvpx) and AV1 (SVT-AV1) are BSD-licensed in every build. The check under [How this is kept up to date](#how-this-is-kept-up-to-date) holds that build copyleft-free; pixelflux's own inventory is its [LICENSES.md](https://github.com/selkies-project/pixelflux/blob/main/LICENSES.md). |

pixelflux and pcmflux encode and decode the video and audio through the codec
libraries they link, and the RTP layer packetizes their output through an
`EncodedPacket` container of its own, so the stack carries no FFmpeg library.

Everything else a Selkies installation links or loads is LGPL or permissive.
The container images also install the distribution's `ffmpeg`, a GPL build on
Debian and Ubuntu, for the desktop's own players and browsers, so an image is
distributed under GPL terms for that part as well.

## The default is GPL-enabled

pixelflux builds with its GPL components on by default (libx264 for software
H.264, x265 for software H.265), and that is the supported default for every
deployment — the wheel, the native packages, the container images, and the
AppImage. Naming pixelflux's `openh264` feature in place of `gpl` in the
workspace's `Cargo.toml` is the opt-out for operators who need a copyleft-free
build; the sections below describe both.

## What a non-GPL deployment contains

With pixelflux's `openh264` feature in place of `gpl`: Selkies, pixelflux,
pcmflux, and the web client under the weak copyleft of MPL-2.0, the permissive
crates above, and the LGPL libraries they load (libpulse through pcmflux and
`libpulse-binding`, glibc, libde265 through pixelflux). Nothing
GPL but the GCC runtime (libgcc_s, and libstdc++ for OpenH264), whose runtime
library exception covers the program linking it, and nothing that reaches
beyond its own files. The WebRTC stack
packetizes pixelflux/pcmflux output and brings in no media library of its own.

## What the default (GPL-enabled) deployment adds

An installed Selkies adds libx264 and x265 through the pixelflux it links,
both GPL-2.0-or-later, and the container images add the distribution's
`ffmpeg` on top, so a deployment that ships them is distributed under GPL terms
for those parts.

## How this is kept up to date

`scripts/check-licenses.py`, `deny.toml`, and the `Licenses` workflow
(`.github/workflows/licenses.yaml`) hold this page to the dependency graph, on
every push to `main` and every pull request.

The script resolves the crate graph of both configurations with
`cargo metadata` over the four Linux release targets, normal dependencies only:
the workspace as committed, pixelflux with its `gpl` feature, and a copy of the
workspace manifest naming `openh264` in its place, resolved against the
committed `Cargo.lock`. It ranks each crate's license expression, overlays the
native libraries the bindings link, load, or compile in, and reads the license
each npm package's entry in the addons' `package-lock.json` records. It fails
when a copyleft component appears anywhere but libx264 and x265 in the GPL
build, when a crate's own license is LGPL (a static link cannot keep it
replaceable), when a runtime npm package is copyleft or LGPL, when a crate or
package has no license metadata or one the script does not classify, when a
native binding, a direct dependency, or a vendored crate is not described in
it, and when a generated table on this page differs from what the graphs
yield. Regenerate the tables with:

```sh
python3 scripts/check-licenses.py --write
```

cargo-deny audits the shipped graph on its own (`cargo deny --exclude-dev check`):
crate licenses against a permissive allow list plus MPL-2.0, with x264-sys's
GPL as the one exception; crates.io and the pinned pixelflux, pcmflux, and
smithay repositories as the only sources; and the RustSec advisories, every one
it ignores listed in `deny.toml` with the reason. pixelflux and pcmflux carry
the same gate over their own graphs (pixelflux's
[LICENSES.md](https://github.com/selkies-project/pixelflux/blob/main/LICENSES.md)).
