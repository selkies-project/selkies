# pcmflux 2.0.0

A major release rewriting the audio capture and Opus encode core from C to Rust behind native PyO3 bindings — adding a mic-uplink playback path, RFC 2198 RED loss recovery, multichannel (surround) Opus, and zero-copy frame delivery. pcmflux is the audio sibling of pixelflux: the capture thread encodes inline and hands each frame to a separate delivery thread, so a slow or GIL-blocked Python callback never stalls the audio pump.

## Breaking Changes

- **Capture/encode core rewritten in Rust** : the C sources and the ctypes wrapper (`pcmflux/__init__.py`) are replaced by a single pure-Rust PyO3 extension — `import pcmflux` now loads a native CPython extension directly
- **Python bindings migrated from ctypes to PyO3** : `AudioCapture`, `AudioCaptureSettings`, and `AudioFrame` are native classes, and the capture callback receives a zero-copy `AudioFrame` (buffer-protocol object) instead of a raw owned buffer. No manual memory management
- **Old `deferred_free` / `OwnedAudioFrame` ownership model removed** : frames are always zero-copy now (the native buffer protocol works on every supported Python version), so the PEP 688 / Python-3.12-only path is gone
- **Python requirement raised to `>=3.9`**

## New Features

- **Mic-uplink playback** : new `AudioPlayback` + `AudioPlaybackSettings` — decode the client's Opus mic stream (with optional RED recovery) and play PCM into a virtual PulseAudio sink. API: `start(settings)`, `write(opus_bytes)`, `write_red(opus_bytes, primary_ts)`, `stop()`, `is_running`. Playback is mono/stereo (surround is capture-side only)
- **RFC 2198 RED redundancy** : `red_distance` (0–4) prepends redundant copies of recent Opus packets so a client on a lossy transport rebuilds a dropped packet from the next one it receives; `0` (the default) disables it for reliable transports. This is application-level RED — no libopus in-band FEC or DTX
- **Multichannel (surround) Opus** : 5.1 and 7.1 via the Opus multistream API using Chromium-compatible `multiopus` channel layouts; accepted channel counts are 1, 2, 6, or 8
- **Zero-copy `AudioFrame`** : the encoded chunk is exposed read-only through the buffer protocol (`bytes(frame)` / `memoryview(frame)` / `len(frame)`) with no copy, across CPython 3.9–3.14, and carries a `pts` sample timestamp; buffers recycle back to a pool when the last reference drops
- **Live bitrate updates** : `AudioCapture.update_audio_bitrate(bps)` retunes the Opus bitrate mid-session with no restart (applied on the next frame, only when it changed)
- **Silence gate** : bit-exact all-zero frames are dropped before encoding (default on) — no packet, no marker — while the `pts` clock keeps advancing so timestamps never drift
- **Native audio wire header** : each chunk carries a `0x01` tag by default (`[0x01, 0x00]` when there is no redundancy) so WebSocket transports skip an extra copy; set `omit_audio_header=True` for bare Opus (WebRTC/RTP)
- **Tunable capture** : validated `frame_duration_ms` (2.5 / 5 / 10 / 20 / 40 / 60 ms), configurable `latency_ms`, and VBR/CBR via `use_vbr`
- **`atexit` handler** : every live capture and playback is cleanly stopped and joined before interpreter shutdown

### AudioCaptureSettings Fields

| Field | Type | Default | Purpose |
|-------|------|---------|---------|
| `device_name` | str/bytes/None | None | PulseAudio source (a sink's `.monitor` for desktop audio); None/empty = system default |
| `sample_rate` | int | 48000 | Capture + Opus sample rate (Hz) |
| `channels` | int | 2 | 1/2 (mono/stereo) or 6/8 (5.1/7.1 surround) |
| `opus_bitrate` | int | 128000 | Opus target bitrate (bps) |
| `frame_duration_ms` | float | 20.0 | Opus frame size; one of 2.5, 5, 10, 20, 40, 60 |
| `use_vbr` | bool | true | Opus VBR (true) vs CBR (false) |
| `use_silence_gate` | bool | true | Drop bit-exact silent frames |
| `debug_logging` | bool | false | Verbose per-frame logging |
| `latency_ms` | int | 0 | PulseAudio target latency; 0 = ~20 ms floor for a prompt first frame |
| `omit_audio_header` | bool | false | Emit bare Opus with no `0x01` wire tag |
| `red_distance` | int | 0 | RFC 2198 redundant copies per frame (clamped 0–4; 0 = off) |

## Encoding & Pipeline

- **PulseAudio S16LE capture** : pulls interleaved 16-bit PCM from a PulseAudio record stream (PipeWire is supported through its PulseAudio compatibility layer) and reassembles it into fixed-size Opus frames; a named source is validated up front via an introspect probe
- **Opus in low-delay mode** : `LowDelay` for mono/stereo (the `opus` crate) and `RESTRICTED_LOWDELAY` for surround (the raw multistream API via `audiopus_sys`)
- **Surround via Opus multistream** : 5.1 → 4 streams / 2 coupled, 7.1 → 5 streams / 3 coupled, using Chromium-compatible channel mappings so a browser decoder inverts them exactly
- **RFC 2198 RED framing, allocation-free** : up to `red_distance` prior packets are assembled in place into a pooled buffer; redundant blocks whose 14-bit timestamp offset or 10-bit length would overflow are skipped, and silent frames never enter the RED history
- **Digital-silence gate** : a single vectorized compare against a zero reference drops bit-exact silent frames; any real noise floor is encoded normally
- **Live bitrate retune** : each frame re-reads the bitrate mirror and calls the Opus bitrate control only when it changed, so an unchanged frame costs nothing
- **Sample-accurate `pts`** : a running per-channel sample counter, advanced once per frame, used for RED offsets and client ordering
- **Off-audio-path delivery** : the capture thread pumps PulseAudio and encodes inline, then hands each frame through a bounded drop-oldest ring to a separate delivery thread that runs the Python callback; the GIL is acquired once per delivered frame, and the capture thread never touches it

## Resilience & Fixes

- Capture and delivery are decoupled by a bounded **drop-oldest `DeliveryRing` (capacity 8)**, so a stalled callback drops the oldest queued frame instead of blocking the PulseAudio pump
- Encoded buffers are **pooled and recycled** on `AudioFrame` drop (up to 16 retained), keeping the steady-state emit path allocation-free
- Capture and delivery threads run at **elevated priority** (worker `nice -15`, delivery `nice -10`), best-effort, so audio does not stutter under CPU saturation
- The PulseAudio mainloop is pumped with a **bounded ~20 ms timeout**, so a pending stop is observed within ~20 ms even if the source delivers nothing
- A single `stop_state` atomic is the one source of truth: an external stop is stored **inside the lifecycle lock immediately before join**, so a stop can never be lost, and a re-entrant stop/start issued from inside the callback is detected by thread id and **short-circuits instead of self-joining** (which would otherwise deadlock)
- The **GIL is released around join** — joining the capture thread transitively joins the delivery thread, whose in-flight callback needs the GIL
- A single **`atexit` sweep stops and joins every live capture and playback** before interpreter finalization (dual weak registries), so no detached thread survives into teardown
- **`write` / `write_red` are gated on a live worker**, so feeding a dead or failed playback stream raises instead of silently swallowing audio; RED playback dedupes by timestamp so no frame is double-decoded when there is no loss
- Logging is **EPIPE-safe** (a broken output pipe cannot unwind out of the capture thread), the PulseAudio introspect FFI callback is wrapped in `catch_unwind`, and a callback exception is reported unraisable rather than propagated across the boundary

## Build & CI

- **Wheels published as GitHub release artifacts** via GitHub Actions + `cibuildwheel` (v4.1.0): pre-release builds on every push to master (`pre-release.yml`), full releases on semver tags (`release.yml`, which requires a matching `release-notes/<tag>.md`)
- Per-version wheels for **CPython 3.9 through 3.14** (free-threaded and PyPy builds skipped)
- **`manylinux_2_28` and `musllinux` (Alpine/musl) wheels, for both `x86_64` and `aarch64`**
- Rust installed via **`rustup`**; the extension is pure Rust (no C sources)
- System dependencies: **libpulse** (PulseAudio) and **libopus**; where no system libopus is present, `audiopus_sys` builds a vendored copy via CMake
- **Rust API docs** built with `cargo doc --document-private-items` and published to **GitHub Pages** on every master push (`rustdoc.yml`)
- **PyO3 `0.29.2`, full CPython API (not abi3/limited)** — the full-API buffer-protocol slot is what makes the zero-copy `AudioFrame` valid on CPython 3.9/3.10, which the limited API cannot express before 3.11
- Rust crates: `opus` 0.3 + `audiopus_sys` 0.2 (Opus), `libpulse-binding` 2.30 (PulseAudio), `bytemuck`, `libc`
