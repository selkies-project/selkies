# PixelFlux 2.2.1

A fix release: an X11 H.264 capture that came up in software because it was larger than the GPU encoder's maximum picture now returns to the GPU encoder once a resize brings it within that size.

## Resilience & Fixes

- **A resize returns an X11 H.264 capture to the GPU encoder** : a capture larger than the engine takes (NVENC's 4096x4096, exceeded by an 8192x4096 Xvfb root captured before the client's first resize) started on x264 and stayed there at every later size; a size change now builds the session again where the encode node has an engine for it, as the VP8, VP9, H.265, and AV1 sessions already did. A session forced to software, or demoted after repeated hardware failures, keeps its software encoder
